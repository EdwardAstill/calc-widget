# Shadcn Registry Frontend Design

**Date:** 2026-09-02

## Goal

Replace the current custom Vite frontend with a simpler frontend built from
shadcn components backed by Base UI, and publish the calculator as an
installable GitHub registry block.

The symbolic calculator's existing domain and solver behavior is already
accepted. This change preserves that behavior while replacing the presentation
layer and development host.

## Success Criteria

- `bunx shadcn@latest add EdwardAstill/calc-widget/scientific-calculator`
  installs a reusable calculator block into an existing shadcn project.
- The registry pins Base UI and uses current shadcn defaults rather than relying
  on whatever primitive library a future CLI happens to select.
- Every visible or interactive UI element uses a shadcn component when shadcn
  provides one.
- The frontend has a compact two-column desktop layout that stacks on smaller
  screens.
- No custom theme, palette, font, gradient, shadow system, custom component
  variant, or shadcn primitive override is introduced.
- The parser, reducer, MathML generation, operation insertion, worker protocol,
  Pyodide client, Python adapter, and solver behavior remain intact.
- The repository uses Bun's native HTML development server and bundler; Vite is
  removed.
- Type checking, linting, domain tests, UI tests, production bundling, registry
  validation, a clean-project installation check, and browser smoke testing all
  pass.

## Product Boundary

The deliverable is one reusable `registry:block` named
`scientific-calculator`. It is not a standalone application template.

The repository keeps a minimal local preview page only so the canonical block
can be developed and verified. That page is not a second implementation and is
not distributed by the registry.

## Repository Structure

The canonical installable source moves under:

```text
registry/
└── scientific-calculator/
    ├── scientific-calculator.tsx
    ├── components/
    ├── dsl/
    ├── solver/
    ├── generated/
    ├── help.md
    ├── model.ts
    ├── operations.ts
    └── reducer.ts
```

Pure domain and solver modules move without behavioral redesign. Their tests
remain in the repository but are excluded from the installed registry payload.
The top-level component and all presentation components are written from
scratch.

The other relevant repository files are:

```text
registry.json          # GitHub source-registry catalog
components.json        # local preview's shadcn configuration
bunfig.toml             # Bun static server + Tailwind plugin
components/ui/          # unmodified Base UI shadcn primitives for local preview
lib/utils.ts            # shadcn utility dependency
preview/
├── index.html
├── main.tsx
└── globals.css         # generated shadcn defaults only
```

The preview imports `registry/scientific-calculator` directly. There is no copy,
generation step, or alternate demo component that can drift from the registry
source. The local `components/ui/` files are generated by shadcn and remain
unmodified; registry consumers receive their equivalents through declared
`registryDependencies`.

## Removed Frontend

The following current presentation infrastructure is removed:

- Vite configuration, plugin, scripts, and metadata.
- `src/App.tsx`, `src/main.tsx`, the current custom stylesheet, and unused Vite
  assets.
- The existing `ScientificCalculator` JSX and every component under the current
  calculator `components/` directory.
- The custom dark theme, Google font imports, gradients, decorative title mark,
  bespoke buttons, bespoke cards, and all related selectors.

Current pure TypeScript and Python calculator logic is retained and moved to
the canonical registry tree. UI orchestration is reconnected to the same public
state transitions and solver protocol.

## Registry Design

The root `registry.json` follows the official `registry.json` and
`registry-item.json` schemas and contains:

- A `registry:base` item that fixes the Base UI-backed shadcn configuration,
  neutral base, CSS variables, and Lucide icons.
- A `registry:block` item named `scientific-calculator`.
- Explicit file targets under
  `@components/scientific-calculator/` for every installed source file.
- `registryDependencies` for the shadcn primitives used by the block.
- Package dependencies for `lucide-react` and `pyodide`.
- Concise installation and first-use documentation.

The block includes committed generated help content so consumers do not need
the repository's Markdown generation script. It includes the worker and Python
adapter because they are runtime dependencies of the calculator, not preview
infrastructure.

The planned shadcn dependencies are:

- Alert
- Badge
- Button
- Card
- Checkbox
- Dialog
- Dropdown Menu
- Field
- Scroll Area
- Separator
- Spinner
- Tabs
- Textarea
- Tooltip

The GitHub registry model is source-based: no registry server and no committed
generated `public/r/*.json` artifacts are needed. This follows the
[GitHub registry documentation](https://ui.shadcn.com/docs/registry/github).

## UI Design

### Page header

The block starts with a small title and one-line description. A default ghost
Button opens calculator help in a Dialog. The block does not add branding,
version chrome, a custom shell, or decorative artwork.

### Left column: expression builder

A default Card contains:

- A Field label and status Badge.
- A controlled Textarea for the calculator DSL.
- Default Buttons for Add/Save relation and Clear.
- A visible, disabled Plot Button marked as V2.
- Field validation text for parser diagnostics.
- A live native MathML preview separated from the editor controls.
- Tabs for Arithmetic, Scientific, Algebra, and Calculus operations. Each tab
  renders its existing operation templates as default small/outline Buttons.

Tabs keep all 30 operation controls available without presenting them at once.
Operation insertion remains selection-aware.

### Right column: relations and results

A Relations Card contains:

- A relation count Badge and short system explanation.
- An empty state or a Scroll Area of saved relations.
- Each relation's native MathML, original DSL source, current edit state, and a
  disabled shadcn Checkbox for the retained V2 plot affordance.
- A Dropdown Menu for Edit and Delete so row actions do not dominate the list.
- A Calculate Button below the list.

A second Card renders result and engine state. Default Alert, Badge, Spinner,
Separator, and Button treatments cover idle, loading, solved, diagnostic,
failure, and retry states. Existing result distinctions and accessible messages
remain, but no custom status color system is added.

### Responsive behavior

The block uses two columns at an appropriate desktop breakpoint and stacks into
the same logical order on smaller widths:

1. Expression editor
2. Live preview and operations
3. Saved relations
4. Calculate action and results

No fixed viewport height or internal desktop-only sizing is required.

## Styling Constraint

All UI primitives come from shadcn's Base UI variants and retain their shipped
appearance. The block may use ordinary Tailwind utilities for grid, flex,
spacing, sizing, overflow, and responsive behavior. It may also use shadcn's
existing semantic tokens such as `background`, `muted`, `border`, and
`destructive`.

The implementation must not:

- Modify the source or variants of installed shadcn primitives.
- Introduce custom CSS variables or brand colors.
- Add a custom font.
- Add gradients, decorative backgrounds, bespoke shadows, or animation.
- Recreate a control in raw HTML when a suitable shadcn component exists.

Plain semantic wrappers and native MathML are allowed because shadcn does not
replace document structure or math rendering.

## State and Data Flow

The data flow remains:

```text
Textarea change
  → parse and validate
  → native MathML preview
  → save relation through existing reducer
  → preflight all saved ASTs
  → worker client sends validated AST data
  → Python adapter constructs SymPy objects
  → worker response updates solver state
  → shadcn result components render the outcome
```

The registry component continues to accept an optional injected `SolverClient`
for deterministic tests and host integration. When no client is supplied, it
creates and disposes its own worker-backed client.

## Errors and Accessibility

- Parser errors are associated with the Textarea through Field validation and
  accessible descriptions.
- Empty-system attempts, unsupported input, underdetermined and overdefined
  systems, unresolved results, no-solution results, engine failures, and retry
  actions retain distinct text.
- Async solver state uses `aria-live="polite"`; immediate validation failures use
  alert semantics only where interruption is appropriate.
- Dialog focus management, Dropdown Menu keyboard behavior, Tabs, Checkbox,
  Tooltip, and Scroll Area behavior come from shadcn's Base UI primitives.
- Icon-only actions retain explicit accessible labels.
- Disabled V2 controls explain their status through visible text or Tooltip
  content and remain noninteractive.

## Bun Development Host

Bun 1.4 serves the preview directly from its HTML entrypoint:

```text
bun preview/index.html
```

Bun provides bundling and hot reload without a Vite configuration. The Bun
Tailwind plugin processes the shadcn/Tailwind CSS used by the preview. The
production preview bundle uses Bun's HTML build entrypoint and a clean output
directory.

The help Markdown generation continues to run before development, tests, and
builds so the committed generated content cannot silently become stale.

## Testing and Verification

### Preserved tests

Pure parser, analyzer, MathML, operation insertion, reducer, preflight, solver
client, Python adapter, and Markdown generation tests remain. Path-only updates
are allowed when the canonical source moves.

### Rewritten UI tests

Fresh tests exercise user-visible behavior rather than old markup or class
names:

- Add, edit, and delete a relation without duplication or reordering.
- Show live MathML and parser diagnostics.
- Insert operations at the selection.
- Calculate all saved relations as one system and render every solution.
- Render each solver diagnostic and retry state.
- Open and close notation help.
- Keep Plot and row plot checkboxes visible and disabled.
- Preserve accessible names, dialog semantics, status output, and keyboard use.

### Registry verification

- Validate `registry.json` and its items against the official schemas.
- Verify every declared source path and target path.
- Verify the Base UI pin and all shadcn dependencies.
- Resolve the local registry payload into a temporary clean shadcn project and
  typecheck/build that project.
- After the commit is available on GitHub, run the documented
  `shadcn registry validate EdwardAstill/calc-widget` command and repeat the
  installation check from the GitHub address.

### Repository verification

- Generate help content.
- Run Bun and Vitest test suites.
- Run TypeScript type checking.
- Run Oxlint.
- Build the preview with Bun.
- Start the Bun preview and smoke-test the calculator at desktop and narrow
  widths, including interaction, console output, and light/dark default themes.

## Non-Goals

- Changing the calculator grammar, relation semantics, solver protocol, or
  Python solving behavior.
- Implementing plotting or enabling any V2 control.
- Publishing a standalone application template.
- Adding customization options, themes, persistence, accounts, analytics, or
  unrelated refactors.
