# Shadcn Registry Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Vite/custom-CSS frontend with a Base UI-backed shadcn calculator block, publish it through the repository's GitHub registry, and use Bun's native HTML server for local development.

**Architecture:** `registry/scientific-calculator/` is the canonical installable source and contains the preserved calculator domain/solver modules plus a new shadcn presentation layer. A root `registry.json` publishes that tree as one block and pins Base UI through a registry base item; a minimal Bun preview imports the canonical block directly.

**Tech Stack:** Bun 1.4, React 19, TypeScript 6, shadcn CLI, Base UI, Tailwind CSS 4, Pyodide 314, SymPy, Vitest, Testing Library, Oxlint

**Spec:** `docs/superpowers/specs/2026-09-02-shadcn-registry-frontend-design.md`

## Global Constraints

- The installable item is `scientific-calculator`, a reusable `registry:block`, not an application template.
- Use Base UI through shadcn's default `base-nova` preset, neutral theme, CSS variables, and Lucide icons.
- Every visible or interactive element must use a shadcn component when shadcn provides one; plain semantic wrappers and native MathML are allowed.
- Do not modify generated shadcn primitives or add component variants, colors, fonts, gradients, decorative backgrounds, shadows, or animation beyond the exact `base-nova` output generated by shadcn.
- Tailwind classes in calculator-owned code are limited to layout, spacing, sizing, overflow, responsive behavior, and existing shadcn semantic tokens.
- Preserve parser, reducer, MathML, operation insertion, solver protocol, Pyodide, Python adapter, and solver behavior.
- Keep the Plot button and per-relation plot checkboxes visible, disabled, and labeled as V2.
- Delete the existing frontend and Vite host; the user explicitly authorized this deletion.
- Use `apply_patch` for authored edits and preserve unrelated user changes.

// scripts/render-solver-source.ts
import { mkdirSync, readFileSync } from 'node:fs'
import { dirname, resolve } from 'node:path'
import { fileURLToPath } from 'node:url'

export function serializePythonSource(source: string): string {
  return `// Generated by scripts/render-solver-source.ts.\nexport const SOLVER_SOURCE = ${JSON.stringify(source)}\n`
}

if (import.meta.main) {
  const root = resolve(dirname(fileURLToPath(import.meta.url)), '..')
  const source = readFileSync(
    resolve(root, 'registry/scientific-calculator/solver/solver.py'),
    'utf8',
  )
  const output = resolve(
    root,
    'registry/scientific-calculator/generated/solver-source.ts',
  )
  mkdirSync(dirname(output), { recursive: true })
  await Bun.write(output, serializePythonSource(source))
}

- [ ] **Step 3: Implement editor parsing and the MathML boundary**

`parseEditor` must preserve the current parser messages:

```ts
export function parseEditor(source: string): EditorParseState {
  if (!source.trim()) return { kind: 'empty' }
  try {
    const ast = parseRelation(source)
    return { kind: 'valid', ast, mathml: relationToMathMl(ast) }
  } catch (error) {
    return {
      kind: 'invalid',
      message: error instanceof Error
        ? error.message
        : 'This expression is not valid.',
    }
  }
}
```
